# 主绘制根分派与事件接管

`game/draw_dispatch` 恢复原 `51c736` 与 `4d9733` 的有序分派。资源根使用不透明令牌；仍未确定所有加载器的持有关系，字段保留原全局地址名称，避免把事件模型误称为普通玩家/NPC。

| 主流程 | 4a4701模式 | 对象槽与额外阶段 |
|---|---|---|
| 8 | 1 | 槽4 = 733e28根 |
| 56 | 1 | 槽4 = bef77c根，槽0 = bef780根；两者必须存在 |
| 72 | group4用10，否则1 | 槽4 = 721b28根 |
| 16，event_state7 | 1 | 对象数组全空，跳过事件阶段 |
| 16，其他event_state | 1 | 槽4=721b28、槽0=721b34；state1/8才有槽5=721b2c；先4e1473再4d9733 |
| 其余，包括2/4/64 | 0 | 全空数组，后续灯光策略使用scene_root |

原描述符的52对象、模式和shadow字段先全部清零；该入口并未把图形设置直接填入shadow字段。选择失败保持输出不变；缺失gallery必需根显式拒绝，避免复现原空指针访问。

事件模式 `721ec4` 的行为：0先查询722454声音缓冲，正在播放才执行特殊场景并接管；1先执行特殊场景，再查询播放状态，总是接管；2只调用音频压低/恢复，然后正常绘制；其他值直接回到正常绘制。状态查询结果必须为0且flags位0设置。该接口是DirectSound GetStatus，位0是播放状态，不能按视频播放判断；参见[Microsoft GetStatus](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee418070(v=vs.85))。`4e01e4` 实际操作722334音量，并非绘制函数。

`bk_draw_dispatch_run` 通过调用方提供的真实服务执行这些阶段，保留事件描述符编辑和服务顺序。任何缺失的必需服务显式失败，服务失败停止后续调用，不宣称回滚已发生的外部操作。`bk_draw_dispatch_lighting` 只转移最终对象与模式，保留原灯注册表与scene_root。

- 单元检查必需服务预检、各回调失败后不再执行后续阶段、灯资源保留及原子选择失败。
