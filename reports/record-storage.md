# 结局动作记录持久化与重启回放

2026-09-30。正常应用现在保存全部五组结局动作记录，重新启动后由同一个进程记录所有者恢复，鉴赏回放读取恢复后的对应路线。文件为可写输出目录中的 `save/records.bkr`，与区域存档和 `save/unlocks.bku` 分开。

`save/record` 只借用两条 retained 数组、动作工作区和计数的视图，不依赖 game、scene、Vulkan 或 libnx。完整保存五组各 120004 字节，包括未使用的动作字和有符号计数的位模式；不伪造动作、结束标记或解锁状态。原版 600020 字节 Gray 格式提供显式内存编解码，不自动读取或修改原游戏目录。移植格式加 32 字节版本、维度及 CRC32 头，逐字按小端编码，不转储 C 结构体。

应用启动按原 4E6F33/4E6F38 顺序先读解锁表再读记录；缺少记录文件保留初始零值，损坏文件明确失败。flow10 退出按原 4EB8FF 顺序，在停止场景之前保存记录，随后由结束对话原有逻辑提交解锁表。两份文件分别提交，不宣称跨文件事务。写入失败不执行后续场景停止、延迟退役或解锁行发布。旧构造接口保留为显式内存诊断，正常应用使用必须提供记录存储的入口。

文件层先校验已有文件，再写同目录 `.part`，flush/fsync/close 成功后使用既有替换及 `.bak` 恢复策略。损坏进度不会当作空文件覆盖。600KB 编码临时区在堆上分配；不复制原版的大栈帧、短读后发布或无校验覆盖行为。不保证目录 fsync、断电持久性或多进程合并。

原指令证据固定于 SHA-256 `a3c9360321d4e4687b1a8a095f514c6c38c327119d8f52aafe664f02bc51679e` 的 EXE。测试执行完整 50CAA2/50CC47 和真实 50D245，仅路径与 Win32 文件 I/O 使用测试替身。普通和 ASan 构建各 16 次完整写入、17 次完整读取，共比较 19800660 字节，差异为零；包括原有 Gray 文件往返。原 INVALID_HANDLE、读取失败与短读的危险结果单独记录，不作为移植版缺失文件默认值。

应用探针从空记录和未解锁状态开始，真实菜单命中产生一个动作，再由实际输入累计全部 11 次完成条件，运行真实动画、音频及结束等待，生成动作 21、保留路线和工作解锁位。随后走应用退出保存、结束对话和标题返回。回放由另一个操作系统进程启动，通过标题及鉴赏菜单读取并播放刚才的记录。测试明确设置故事交接、选择阶段及初始拖动状态三个边界，没有预填记录、完成次数、20 秒等待或解锁表；因此不是完整自然故事与全部输入路径验收。
