# 结局镜头目标、活动相机与可选命中节点

2026-09-29。针对“结局人物显示不完整，只能看到腿”的实际反馈，修复普通结局的加载目标传递、公共镜头按钮节点绑定和 UI 相机来源。保持现有 4:3 内容区；没有进行 16:9 改造。完整入场父控制器和自然结局流程仍未完成。

## 已复现的原因

`local/ending-framing-before.log` 保存了真实故事入口的首个活动帧：原加载器已得到目标 `(-9.72619343, 12.7181673, -0.75999999)`，但场景中的 `frame.camera_values` 和 `control.targets` 仍为零。随后 `4bb0a4` 围绕世界原点计算镜头，组0头部的归一化屏幕 Y 为 `-4.49270344`，远在可见区 `[-1,1]` 上方；膝部仍在可见区。该诊断继续进入组1时又因可选命中节点缺失而失败，不能记为五组全部通过。

本次修正后同一组0首帧头部 Y 为 `-0.7772277`。五个角色的两种输出目标均成功构造、更新和绘制，头部采样值见 `local/ending-framing-final-host-framing.log` 和对应 ASan 日志。这是当前移植场景的实际数值复现与修复，不是 Windows 原版截图对照。

## 实现

`scene/ending_normal_session.normal_load` 将资产加载器在背景插入之前捕获的三组目标复制到真实 `control.targets`，第一组复制到 `frame.camera_values`；相机表也从实际加载配置传给帧分派器。目标保持原加载快照，直到原控制器显式刷新，不改成每帧追踪的新焦点。

公共控制 `4d7ac4` 需要的输入顺序为 `721ef4 / 719b40 / 721f08 / 721f28`。普通加载器现在传入已发布的主体节点 `0 / 缺失的独立别名 / 5 / 13`，不再错用加载快照的三项排列。普通预设切换、目标切换、复位从旧发布缓存读目标。另一加载器的 `719b40` 尚未恢复，没有用其他节点替代。

自动镜头 `4e1711` 使用实际 `719448` 对应的 `A_kuch`，手动瞄准 `4e1d16` 使用 `721ef4` 对应的 `A_kao`。预设路径不再查询其不使用的头节点；FOV 门控借用真实 `previous_flow` 和辅助 gate。UI 的角度判断改读活动相机锚点1的 local，原来误读了相机动画轨道根节点的 local。

两个日文零基组1/2模型确实缺少节点 `20,21,22,23,29,30,37,38`，其中六个属于线段命中端点。原函数在缺节点时留下部分栈数据未初始化。保留严格的 `bk_ending_ui_pick_targets` 接口，同时给运行时选择器增加显式的 `bk_ending_ui_pick_available_targets` 策略：仅排除缺少端点的线段，不伪造坐标、距离或命中；存在但无效的矩阵、截短绑定表仍失败。全缺失返回未命中。此策略替代原未定义路径，不声称与任意原栈残值等价。

## 验证结果

普通和 ASan/UBSan 各执行10个真实故事入口：五角色分别使用 `960×720` 和 `1280×720` 输出，每种构建1,390个活动帧、50次真实工具栏点击、20次独立相机适配调用。目标传递、旧缓存读取、三目标切换、预设与复位、自动/手动节点来源、活动相机 local、黑边和 GPU 回收基线均通过；两种构建的逐角色镜头摘要一致。新增测试入口为 `tools/ending_framing_probe.c`，已登记 CMake 和 `test-host.sh`。

两种构建的既有画幅回归各12组、3,368个场景帧、102,988,800个 UI RGBA 字节，界面像素差0；3,392次实际绘制批次检查、136次弹窗视频变化、24次显式 phase7 空绘制通过。新增配对检查覆盖相机、投影、五个 actor 的全部 local/world/parent-world 缓存及实际提交队列拓扑，12/12相同。

**完整三维像素诊断仍只有8/12达到原有阈值，最大显示通道差33/255。** 与先前只看到腿时的11/12结果不同；现在取景已经改变。没有放宽或删除阈值，也没有把诊断程序退出0当作完整画面通过。上述 CPU/队列一致性缩小了排查范围，但不证明 GPU 输入的所有字段或最终像素完全等价，差异来源仍需继续检查。

原版固定 EXE 对照完成24,000组公共控制/131,741次服务、4,000组相机角度、16,000组线段、1,612组完整命中查询，以及1,885帧选择与游标组合/147,522个顶点；这些定义良好样本的结果精确一致。缺节点策略另由单元和真实资源回归验证，不混入原版等价计数。固定 EXE SHA-256 为 `a3c9360321d4e4687b1a8a095f514c6c38c327119d8f52aafe664f02bc51679e`。

普通/ASan各4项定向 CTest、2项架构检查通过。两种构建的实际应用退出回归各196弹窗帧、124黑幕帧和436,800音频帧通过，覆盖返回标题、重入、flow58、末帧重绘、共享 RNG、声音所有权和解锁文件保持。ASan 设置 `detect_leaks=0`，不宣称 LeakSanitizer 通过；没有运行整个 `test-host.sh`。
