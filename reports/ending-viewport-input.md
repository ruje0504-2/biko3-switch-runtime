# 最后界面画幅、光标与图标定位修复

日期：2026-09-29。对应反馈：最后界面与前面剧情比例不同、Switch 显示不全、摇杆不能移动鼠标、图标位置需要核对。

## 原因与实现

`scene/ending_normal_session` 此前直接用渲染目标宽度初始化 1280×960 的原版布局，并把三维画面和 UI 绘制到完整目标。1280×720 目标因此按宽度得到 960 像素高的布局，底部超出目标；前面的剧情和实际游戏已经使用居中的 4:3 内容区域。

现在该场景在构造时调用同一 `bk_camera_fit(...,4,3)`，持有内容 viewport。基本 UI、分支 UI、公共控制缩放、三维目标投影、黑幕和绘制批次均使用该区域的宽高。场景绘制设置对应 viewport/scissor，结束或绘制失败后恢复完整目标。1280×720 的内容为 960×720，左右各留 160；1920×1080 的内容为 1440×1080，左右各留 240。

另一个图标定位问题是 UI 命中投影重复翻转 Y。`bk_camera_projection` 已为 Vulkan 翻转 Y，原适配器随后又使用负的 viewport Y。现改为与实际 Vulkan 光栅化相同的正高度 viewport，保留原 4:3 镜头参数。

此前该场景只在 `pointer_active` 时复制绝对坐标。Switch 左右摇杆提供的是 `move_* / look_*`，没有转换为光标位置。新增纯 CPU `core/input` 虚拟光标：左摇杆及十字键移动，0.18 径向死区，按时间步积分，ZL 为四分之一速度，右摇杆保留给既有镜头控制。触摸坐标减去内容区偏移，位置及实际位移限制在内容区；首次触摸不产生虚构拖动。相同位置同时送入 UI、命中检测和原 11-word 输入；实际位移进入 words6/7。

普通游戏 HUD 已检查：初始化、HUD 准备、投影和绘制原本均使用 `g->viewport`，本次未改变其布局。

## 已取得终态的验证

普通主机和 ASan Vulkan 各执行 12 组配对验证、3,368 个实际场景帧。覆盖两个诊断配置和故事入口、854×480 / 1280×720 / 1920×1080 / 640×960 目标，以及各自相同内容尺寸的 4:3 参考目标。

每次运行检查实际左摇杆移动、触摸偏移、13 个侧栏按钮处于内容区内且命中矩形与布局相同；故事入口通过真实输入打开确认框，再取消返回。检查内容区外像素保持清屏值、目标纵向投影、纯 UI 重绘不消费输入/时间及释放后的 GPU 分配基线。
