# 0.3.5：角色姿态、根坐标与独立播放实例

本阶段继续解决 M1 镜头依赖。六个角色的 CPU 动画及头节点现可正确采样；没有实现 ENVL 蒙皮、动态角色绘制、移动/AI 或真实游戏流程镜头。M1 整体验收及 Switch 实机验证仍未完成。

玩家 `h00` 存在大量稀疏通道；`h04/h05` 含有非单位四元数。`h00` 槽 24 的链式循环次数阈值为 0，原调度器允许该值，首次循环结束就衔接。文件内保存的播放相位会影响新动作过渡起点，不能一概清零，也不能把原生指针恢复到移植进程。

## 工程实现

- `model/animation` 增加线性时间复杂度的稀疏通道预处理，保留非单位四元数。原有相机采样 API 保持兼容；新增姿态请求支持替换无动画轨道的根，再逐级组合。非根、带轨道的根、非有限/非仿射矩阵明确拒绝。
- `model/clip` 新增重复动作请求与显式的 authored 播放器。普通构造仍创建新的播放状态；authored 构造仅接受校验后的播放标量，不使用文件指针。非法种子不会影响普通构造。
- `bk_model_find_frame` 支持原版名字规则；当前绑定必须唯一，缺失或重名返回错误，不随意挑节点。
- `model/playback` 借用不可变模型/XAN，拥有动画、两个时间轴状态和双缓冲姿态。推进失败时，已提交时间和矩阵保持不变。调用方负责模型与配置寿命、半速时间及帧阶段顺序。
- 现有相机诊断场景已改用独立播放实例，仍不填入猜测角色位置，也不宣称已接通游戏镜头。
