# 结局共享黑幕与 UI 尾部

本阶段恢复 `4d677b..4d679d` 和完整 `4d6e6e..4d7432`，包括实际 `495567`、`48cb8a`、语音选择 `4e0032`/`4e0818` 及 `4dfb96` 的表情/眼资源提交。固定原版 EXE SHA-256 为 `a3c9360321d4e4687b1a8a095f514c6c38c327119d8f52aafe664f02bc51679e`。

`scene/ending_ui_tail` 借用当前 frame/control/auxiliary/notice 和真实进度条位置、控制器输入、共享 RNG。新普通提示与辅助提示状态只拥有此前尚未建模的字段；不重置入口状态。共享黑幕直接推进外层 `BkCommonHudState.curtain`，先记录绘制 alpha，再请求 `blocked`。重载控制仍是已实现的 `game/ending_reload`，本阶段没有伪造加载/释放服务。

保留的顺序与边界：

- 普通事件按 14 槽原配置只消费一次。进度增加 `.1f` 或 `.04f`，进度条分别减少 `20*scale` 或 `8*scale`；音频/眼服务之后重新读取后一个分支的 group/目标/方向。
- `495567` 的 mode5/7 先推进闪光再 request；`48cb8a` 先 request 再推进，而且先检查图片句柄。两者共用 slot52 的独立请求位，不能借用四个 notice 位。
- 提示计时虽然除以 10/15，实际条件是商大于零，不是达到 10/15 秒。正计时每次调用即可增加计数。保留有符号 `%4`、32 位计数绕回、8 位序列绕回。
- 辅助 mode6 的图片 UV/缩放使用旧序列值，然后更新序列，再选择真实动作15/16，设置两个实例 chain 字段。动画请求不额外推进或发布角色矩阵。
- `50e479(.01)` 是 alpha setter，更新顶点缓存而非额外 GPU 绘制。后面的 `50e6ba` 才生成快照，不能把它当旋转或重复绘制。
- 声音文件名先提交到共享缓存，再加载/播放；服务失败保留之前已经发生的副作用。未知目标对应的原未初始化路径和越界索引明确拒绝。

`bk_ending_ui_tail_apply` 复用已验证的真实演员/眼资源/音频服务，调用同一个 `BkEndingAudio` 的语音0/1；不创建重复声音所有者。

## 原版缺失语音

真实数据验证发现，原语音表的部分输出本来就没有对应文件。此阶段覆盖的 385 个候选名字中，日文 `bk3_06.pp` 缺少 143 个：普通/接触选择器23个，辅助提示声音120个。其中部分组合来自显式控制器夹具；本报告不声称所有组合在完整玩法中都可达。

原 `4e0956` 先停止并释放旧声音，再把加载器返回值保存到槽；资源不存在时保存空指针。`4ad2bf(null)` 不播放。移植为这些逐项核实的名字保留空槽行为，不让它们引起流程中断。既有文件仍真实解码，新增覆盖文件仍加载；损坏文件或名单外缺失仍报错。严格初始化接口 `bk_ending_audio_bind` 保持必需资源语义，只有实际语音命令采用这份有限名单。
