# 首关应用与持久流程装配

当前源码已接通开发标题 → 首关开场 → phase1 游戏 → 拍照 → 暂停恢复 → 再次暂停返回标题 → 加载页重新进入首关，以及暂停确认退出。不是完整游戏移植，也没有 Switch 实机运行结论。早期组件报告和原 0.3.5 SD 诊断包保持历史证据；本报告描述当前应用装配。

`app/game_preview` 使用真实入口、背景、玩家/NPC、道具、物品、面部/蒙皮、网格阴影、全局节点遍历与统一绘制排序。主流程2采用原 mode0 灯光选择和实际背景雾，4:3 视口为960×720。开场消费原对话/FTT文字、点击声与相机交接；操作HUD和物品提示使用已验证组件，截图在原HUD边界读取本帧世界，照片实际写入BMP。

`app/play_session` 拥有保留的GameFrameState/EntryProgress、common curtain/timer/blocked、flow、pause state与menu cursor。进程boot只运行一次；重建入口借用同一份游戏状态，照片计数不会被入口初始化清零。暂停、加载页使用同一黑幕，不重新构造一份全零common。暂停按51a77c→4f720c只更新音乐及trigger0环境声的音量；背景动画、环境随机计时/RNG和角色控制保持。此前把4f737b用于暂停的装配错误已修正，见`pause-background-fix.md`。当前标题仍是直接进入首关的开发入口，未冒充原版模式8场景选择器。

游戏每次固定更新都提交对应绘制，包括catch-up ticks。帧前只对黑幕fade副本推进以准备透明度；GPU提交之后执行一次真实common_hud，并核对绘制透明度与实际推进一致。这样load_pause才能读取同一帧HUD刚写出的sy_99.bmp，随后才改flow4。零更新重绘不会重复加载、timer或转场副作用。原顺序的逻辑释放立即停止游戏声道，GPU对象保留到最后快照提交后、下一步帧外回收。暂停最终快照不会被finished标记跳过。

flow50已绑定真实标题资源加载与开发首关重入，包含黑幕退出、load、黑幕恢复的完整mode1流程。暂停的返回标题确认实际释放游戏与暂停资源并删除临时截图；恢复保留同一游戏实例。退出对应原466448检测的终止flow58；原4e7671对58没有资源加载，应用在提交最后一帧后执行完整清理并结束循环。未实现的其他目标流明确报错。

## 验证

- `tests/check_game_application.py` 启动实际应用，经1700帧确定性输入回放，从标题完成开场、两次拍照、暂停恢复和二次暂停返回标题。检查日志顺序、最终flow1、照片计数2、两张960×720/24位BMP、临时截图删除与完整RGBA输出。普通与ASan/UBSan运行通过。
- `play-flow-probe` 直接使用同一持久应用所有者，无修改游戏/UI状态的测试捷径。开场994帧自然交接、暂停136帧、返回标题141帧、加载125帧、重入开场995帧、退出141帧；普通与最终ASan/UBSan版本通过，保留照片2。覆盖暂停中除音乐淡出音量以外的全部游戏状态逐字节保持（包含背景计时/RNG）、零更新重绘不推进common、shared common地址不变、释放后游戏声音停止，以及真正的重新加载和退出。
- 独立开发包共126个清单文件、1,795,233,126字节；应用使用复制后的素材回放拍照/暂停/退出，在1621帧正常结束，照片与临时文件检查通过。
- 暂停、flow-loading、热键、操作HUD、capture-file和三项基础回归共8项通过；Python架构边界检查通过。已有原版组件oracle证据沿用各自报告，本次没有把应用回放宣称为完整Windows画面对照。
- 最终Switch NRO使用锁定的mesa-switch NVK构建，ELF未解析符号0。最终NRO SHA256为`107d86f9bc52485909b803ed7271d32fef237d40449dacbaa4292d268a68e452`；具体日志及源码摘要见同目录JSON。
- macOS sanitizer配置为`ASAN_OPTIONS=detect_leaks=0`；该平台不支持当前LeakSanitizer选项，没有宣称通过泄漏检查。主机声音使用明确离线消费端；Switch仍使用libnx audout。
