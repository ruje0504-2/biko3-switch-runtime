# 第二场景物体表面的明暗跳变

2026-10-01。用户纠正定位：第一位角色第二室外场景，书店旁路灯附近最明显；闪烁的是受光物体表面的明暗，而非灯具本身。此前 `de369a84…` 深度修复在实机仍未解决。本轮针对 `bk3_03/m00_11.x` 重新定位，不把雨雪、第一场景发光贴片或室内推断当作结论。

## 原因与实现

发现两个可以分别复现的问题：

1. 明暗贴层排序不稳定。场景将光斑、阴影、污渍等分成透明网格，其中心大多烘焙在世界原点，但部分 pivot 留有 `1.5e-5..6.1e-5` 的导出残差。原交换排序不稳定，优先级排序也可能打乱此前的距离次序；视图旋转后的 float 距离取整又使这些近重合原点反复交换大小。加亮与压暗两种混合不满足交换律，因而出现整片表面亮度跳变。只提高深度精度、或者只改为稳定排序，都不足以消除该复现。
2. 共面阴影的深度竞争。第二场景 `Mesh_HEIG_  0` 的索引 156..158 与墙面共面，三角形划分不同。即使使用新的反向 D32 与独立精密深度行，移动和收敛阶段仍会交替丢失阴影。更多深度有效位不能保证不同三角形的光栅平面完全相等。

改动：

- `game_preview` 为背景显式开启 `bk_actor_render_stabilize_layers`。只对透明排序键，将绝对值小于 `1e-4` 的原点坐标视为零；原几何、法线、灯光、镜头和世界矩阵均保留。包含此背景的全场批次使用稳定的“优先级降序、距离降序、原插入顺序”排序。普通纹理队列及原本没有普通物体时的透明排序旁路保持。
- 新增独立 `bk_draw_order_stable`；严格原版的距离/交换排序 API 仍可调用，原指令 oracle 不改成新策略。鉴赏、结局等未显式启用的 owner 保持其既有排序策略。视图副本继承开关，开启操作使旧快照失效。
- Vulkan 仅为 **lit、不开深度写入、反色混合** 的阴影启用向前的深度偏移：常量 2、斜率 `1/128`。常量 2 单独使用仍失败，加入小于百分之一像素深度斜率的项后通过。加法光斑、普通 alpha、实体和 UI 不加偏移。深度测试继续开启，没有改成穿墙绘制。

以上是有证据的渲染兼容修正，不声称严格逐指令等价。没有新增每帧分配、GPU pass、draw 或同步等待；原二次交换扫描改为一次稳定插入排序，最坏复杂度仍为 O(n²)。未以此宣称新的实机帧率结果。

## 验证方法

`bookstore-lighting-probe` 使用第二场景真实模型、材质、纹理与五盏点光，12 个书店及周边视角。每个视角旋转排序相机、模拟释放后收敛、最后固定；冻结 GPU 光栅矩阵、world、viewer 和灯光，从而只允许排序造成像素变化。测试专用源包含 actor_render 实现，仅为了冻结该快照，生产没有该行为。`--native` 用同一个修复后后端，关闭稳定层策略，作为应失败的排序对照。

每构建 2,520 帧；新策略 RGB 变化为零。旧排序在主动/收敛/固定阶段分别出现 1,291,317 / 2,867,733 / 10,756 个累计变化像素，单帧最高 97,379，最大通道差 63/255。固定阶段统计包含停止点归零的首帧；此后矩阵完全不变，不据此声称静止镜头仍自行闪烁。此测试隔离排序问题，不是完整 Windows 原版截图或实机回放。

`coplanar-shadow-probe` 使用上述实际墙体与阴影三角形，常量颜色隔离深度。两条移动/收敛/固定轨迹，分别检查原共面、前移 .02 和后移 .02 的遮挡，合计六组、360 帧。旧后端共面部分出现 24/33/0 错误采样与 19/32/0 次可见性变化；新后端错误/变化均零，后移阴影保持遮挡。旧后端来自提交 `daf3e6d` 的已保存静态库，只作为普通构建负对照。

普通和 ASan/UBSan 的八项检查包括上述稳定/原排序两组、阴影、排序单测、72 光照公式/描述符案例、混合材质、原第一场景 7,920 帧非共面遮挡，以及真实游戏开场/跟踪/拍照/暂停回归。最终状态与配对统计以 `lighting-surface-layers-verification.json` 为准，不将预期失败的旧排序算作修复后失败。

原 x86 排序 oracle 继续通过：2,400 flush、38,292 项、7,200 cache 调用、14,378 距离对照误差零。29 Python 检查通过。最初新版测试误要求模型中所有材质 power 为零，遇到未使用/其他材质后停止；已去掉这一无关假设，viewer 和着色输入本来就固定。初次失败日志保留于 `local/lighting-bookstore/initial-host-bookstore-invalid-power-assertion.log`。
