# 选择阶段的实际入口、交互与重载

本次接通并验证日文资源的选择阶段 `4D1025 → 48D8E9/494015` 开场，以及实际输入触发的“选择另一项 → 语音等待 → 黑幕重载 → 恢复交互”。这不是完整 phase8 回放或全游戏验收。

## 修复

- 原 session 给无 BOM 的选择阶段传入非空 `bom_disabled`，直接入口的第一次绘制便被真实 renderer 拒绝。现在按实际绑定数量传入该表，保留渲染器的所有权检查。
- 加载器错误地只接受外层鉴赏选择 2/5，导致剧情中的合法 action7 重载失败。`4D1025` 的参数是当前动作编号 0..2，现由原入口/重载分派决定调用，参数边界仍严格检查。
- `4D1C26` 应写 `721EF0=4`，旧适配误写 `721EE4=4`，没有启动选择阶段的开场状态机。现在初始化真实 gate，保留其他阶段/回放释放标签 `721EE4`；同时恢复 `7220E0=0`、目标选择 `721ECC=0`、第二组角色的显示标记和 `4D152C` 动作变体更新。
- `721ED8` 是活跃的背景/前动作选择值，不是最初的鉴赏菜单编号。加载使用并保留这个值；只有原版第二组背景替换分支把它改为 1。第二组普通阶段的 `m02_92.xan` 也属于合法保留背景，现允许从该真实资源继续进入选择阶段，其他组背景检查未放宽。
- 选择阶段拾取原先只检查一个固定半径的屏幕圆，没有运行实际节点投影或写入菜单事件。现在调用已恢复的 `47C334`，读取旧发布世界矩阵并绑定真正的 kind/column/target/ring，首选节点为 4。`4949DC` 使用真实事件/目标值，不再用默认值伪造菜单。
- 表情服务按 `4DFB96` 写两个状态字后选择眼纹理，后续表现阶段再消费状态；不在这里提前采样脸部。菜单动作借用实际 choices 表，命中使用图标当前宽度的一半和原版严格圆边界。

原版加载器确实会写 phase5/6；action6/7/8 的鉴赏重载在外层恢复 phase8。没有为了回放而禁止加载器写 phase，也没有把不同的 action63 路径强行改成 phase8。

## 验证范围

新 `tools/ending_selected_session_probe.c` 使用真实日文 Data、CPU/GPU/PCM 与生产 session。覆盖五组、两变体的 10 个直接鉴赏入口，30 个剧情动作切换边界，30 个 phase8 动作切换边界；后两类明确注入过渡请求，不能称为用户从完整故事自然到达该阶段。

40 个实际场景运行开场直到 gate1，通过公开输入点击投影节点打开菜单，松开确认键选择另一项。后续动作记录、语音等待、黑幕推进、资源重载、旧快照保留与再次进入 gate1 都使用生产代码。30 个 phase8 夹具仅执行真实资源边界，不调用尚未接入的 `48302B/48BCBB`。旧帧回读必须逐字节不变，资源销毁后 GPU 分配返回初始基线。

新 `tests/original_ending_selected_session_oracle.py` 对每次真实重载捕获的前/后状态执行固定 EXE 的四段原始指令。原 memset/strcpy 不替换，只观察并跳过 `4D460B` 的背景 IO。它证明加载器标量/原父状态保留，不替代真实资产、画面或实机验收。

配对检查入口为 `tests/check_ending_runtime.py --suite selected-session`；提供 `--original-exe` 或 `BK3_ORIGINAL_EXE` 时同时运行原版标量对照。具体终态、日志摘要、哈希及验证器修正记录写入同名 verification JSON。

本次普通版与 ASan/UBSan 各通过 70 个入口/边界、39,463 帧、40 次菜单换场和 220 次旧帧重绘，状态 `da0b073adf8e8c8c` / PCM `84966c369317dc40` 完全一致。阶段重载及普通/第三类应用的三组配对回归也通过。原版各 60 次加载、960 个标量值一致；另有 29 项 Python（含架构）、3 项普通 CTest 通过，指定 Mesa NVK 构建成功且 ELF 未解析符号为零。NRO 为 `b09eb9d244015a2de4b4f448c12b6fc099fdd3a72364f0031159de1b516f0891`。

`ending-runtime-xai0f3ai/result.json` 保留首次总检查失败：四组运行时配对已通过，最后原版校验的资源名断言漏写前导反斜杠。修正这一处断言后，对同一组日志重新执行原指令对照通过，结果独立保存为 `selected-session-native-corrected.json`。核对 675 项源码清单，只有该校验脚本哈希变化；运行时、探针和配对二进制未变，因此没有重复运行已经通过的场景帧。新汇总明确记录两次结果，没有把首次失败改写成成功。ASan 未启用泄漏检测；探针另检查实际 GPU 分配回到基线。

## 仍需推进

五类回放 CPU 控制器尚未接入生产 `48302B/48BCBB`，还需进程所有者、真实服务、prepare_final 和完整跨阶段调度。本次审视还发现辅助阶段拾取缺少 kind/column 绑定及表情服务顺序问题，需用实际交互继续修复，不能沿用早期“CPU 服务夹具通过”作为场景已完成的证据。

选择阶段的手势/结束路径也未验收：现有 `selected_ui_byte/uv_reset/fade` 仍写入未被实际 UI 消费的私有字段，重复音频的音量语义也需核对。本次菜单换场通过不能扩展为这些操作全部正确。

自然结束、持久解锁、正式鉴赏前端、完整像素对照（当前仍 9/12）和 Switch 全流程验收没有据此补齐。现有 L/R 与六倍手动镜头设置未改。构建产物只留在构建目录，不生成整包、不推送；Mac 防休眠继续保持。
