# 全局网格提交队列

`model/draw_order` 与 `scene/actor_render` 的跨模型批次恢复原 `42aa47` 的普通/透明两队列提交策略。批次按模型原始深度优先顺序收集，再统一分队列和排序，不能拼接各模型已排序结果。背景和门的诊断绘制已使用共同批次；办公室静态检查也使用同一排序规则。

原 `42b1bd` 把纹理 uint32 标识转换为 float，交换负载却保留键所在槽位，所以并非通常的纹理降序排序。透明队列先距离后优先级，两个交换遍历都保留原算法；普通队列为空时，`42aa47` 跳过整个透明排序。透明优先级交换也不搬移距离缓存，对照程序在计算完成处检查距离，另比最终物体顺序。

距离为 `world * inverse(camera)` 平移行的 XYZ 长度加无符号偏置，保留 world 的 W。平方和先存 float，sqrt 与偏置合并后最终存 float。旧 point(XYZ,W=1) 与多次 float 求和不再用于提交距离。

GPU 纹理采用同一 renderer 内单调创建标识，0 为无纹理；这是明确的可重复分配策略，不声称与 Windows 堆指针排序等价。目前跨模型重复纹理仍独立上传，未恢复原全局纹理注册表的别名关系。CPU 对照提供原始 uint32 键，只证明排序算法。

批次容量最多16,384项，prepare不分配内存、不修改GPU。重复演员出现保留；hidden子树不入队，alpha0网格仍占队列项但跳过实际绘制。批次借用演员，使用准备代数检查过期快照，任何一个失效都在提交第一条绘制前拒绝；调用方负责不提前销毁借用对象。不同灯光阶段分别使用批次与灯快照。
