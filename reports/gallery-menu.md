# 鉴赏菜单控制与真实资源绘制

本批恢复原 `flow0x18` 菜单的 CPU 控制、资源布局、实际纹理和音频绘制边界。`scene/gallery_menu` 对应 4C59C0、4C7916、4C8768 和 51B9B3；`gallery_menu_render` 持有实际图片与不可变绘制快照。尚未注册到应用前端，不能据此声称原标题已能进入鉴赏或完整移植已完成。

原版指令适用 EXE SHA-256 为 `a3c9360321d4e4687b1a8a095f514c6c38c327119d8f52aafe664f02bc51679e`。装配使用日文原始数据，保持只读。

## 原规则与模块边界

- flow18 的加载跳表索引6通向 `4E76EC→4EB93B→4C59C0`；释放跳表索引6通向 `4E783A→4EB945→4C74E3`。五个角色分页、48张常驻图片和第48号动态全图已按原版恢复。
- 上层传入只读 `uint8_t[5][8]` 解锁表；scene 不能引用 save 模块。九类入口中的第九项重复 flag6，五张图片采用 flag2/3/5/6/7，保留非0/1字节。验证用显式解锁夹具，不写入生产存档。
- 初次角色预览图39号的Y为220；角色切换后的Y为232。换页按原序释放九槽、重建八槽，未把两条路径合并为相同布局。
- 点击命中使用上一帧指针位置；控制、菜单绘制之后才采样指针并绘制共享光标与黑幕。共边包含等号，优先命中的按钮返回；锁定项目不激活，也不清除未查询的旧hover标志。
- 四张横向图片按1280×960逻辑内容缩放；最后一张 `gs_01..05.bmp` 按实际内容高度绘成正方形，X为160×scale。保持4:3内容，不拿外层宽屏窗口尺寸替换原比例。
- 确认、关闭、项目hover、角色hover分别使用原音效槽1/3/4/5。背景音乐为 `bk3_02/bg002.wav`。全图关闭使用独立back边沿，不误当确认。
- action0..5分别进入selection0..5，variant为前三项0、后三项1；action6/7都进入selection6，variant分别0/1；action8先设置group/area0，再转flow48；action10返回标题。selection写入在release之前，失败不伪造转场成功。
- 图片关闭时，原程序先绘制再释放。新的render owner把资源保留到下一真实tick，快照绑定具体纹理；纯重绘不推进菜单、光标、黑幕或音频，也不提前销毁纹理。
