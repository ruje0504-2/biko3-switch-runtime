# 鉴赏回放的进程所有者与真实场景接入

本批把已恢复的五类回放控制器接到同一个实际结局场景，使用日文模型、动画、声音、材质、相机、BOM 和 Vulkan 绘制。覆盖的是显式记录路线的回放到退出请求；尚未实现鉴赏前端菜单、自然故事完整记录/解锁链，也没有新增 Switch 实机验收。

## 所有权与服务

`scene/ending_process` 由应用初始化一次，结局入口、资源重载和延迟释放只借用它。交互的表达覆盖字段 6DDE98 与鉴赏的 6C7F78、6DDE52 分开；725704 仍共享 selected action 的同一个字段；三类回放共用一份保存镜头和 6D1BC0 目标。旧场景销毁不得重置新场景的进程状态。应用退出探针另外检查这些字段跨返回标题、重入和晚释放的保持。

生产 phase8 的 48302B / 48BCBB 接入真实服务，分别调度 483AF0、4843AA、4855C9、48758C、488674。`bk_ending_replay_scene_create` 对应原入口 selection6，要求借用记录及解锁表；48D7F2 只执行原保留状态复位。没有制造故事记录或新增返回成功的空后端。

服务使用当前加载器的演员、旧发布节点、相机轨道与预设、实际音槽和材质实例。第二类的 descriptor+190 是循环配置，不能读成 +1F4 的运行次数。第三类反向播放通过真实 402E18 路径处理负时间步，ANIM/MATA/MORP 保持原来的采样顺序。4946B4 / 49490A 在替换声音前写实际保留文件名，含 group0 cue30 写第二语音名的特殊路径。镜头注视使用原 645604 相机锚点。

控制期间退出请求写 frame 的活动别名，之后由现有导出步骤写回 common。直接写 common 会被帧末旧别名覆盖，本批已复现并修正。材质查找仍保持缺省规则，但如果命中尚无可变绘制所有者的附属材质会明确报错，不能伪装成名字缺失。

## 三项明确的兼容修正

原控制器和原模型调度器分别通过服务夹具，不代表组合后在稳定帧率下必定前进。本批真实回放发现三处原逻辑的等待条件问题，以下修正不列为严格原指令等价：

1. 链式动画的速率包含原 `.1` 终点偏移。固定 60Hz 时，h01_03 的片段7可在 source=149.899902、end=150 时已经完成时间轴并链入片段6；原 4855C9 仍等待 source>=end，因而无限循环。原指令本身和移植调度器都复现，部分混合帧间隔也会出现。模型仍保留原采样和链行为；新增只读完成查询，以实际非循环前向片段的 elapsed、duration、chain、active 和未重置 source 判断完成。仅选择回放的片段7/11等待接受此完成条件。源帧重置或重新选片后该条件不再成立，不用放宽浮点阈值，也不改变播放速率。
2. 日文 group1 variant1 的语音可在片段3结束前停止；关闭附加语音时，原状态5直接进入状态6，之后停在片段4而没有请求5。生产绑定显式启用 `wait_for_intro_clip`，先等待片段3完成。普通原版对照默认关闭此选项；新增独立检查确认等待、就绪继续和链完成的计时门限。
3. 第二类日文 h04_02/h05_02 片段12的 duration=20，source跨度40；固定60Hz下，循环末端可观测的source始终落在原 `end-seconds*.3*60*2` 窗口之前，循环20次的计数永远不减少。新增 `finish_crossing` 只读输入，使用实际半速呈现步长、首步抑制、elapsed/duration和source/rate预测下次循环跨界；原窗口继续保留。动画时间/源帧不修改，不伪造到达末帧。原控制器比较令此输入为0，兼容断言另列；真实XAN的预测与原指令实际循环次数逐帧比较。

固定 EXE SHA-256 为 `a3c9360321d4e4687b1a8a095f514c6c38c327119d8f52aafe664f02bc51679e`。原版指令比较只适用于该 EXE。日文素材只读。
