# M1.4 相机轨道采样与运行时检查入口 — 0.3.3

已实现相机 ANIM 的完整位置/旋转/缩放关键帧采样，接入办公室的独立轨道检查场景，并核对控制器的角色输入、平滑和调用顺序。**这是原资源轨道的实际播放，不是已恢复游戏镜头。** 检查入口没有角色锚点、头部朝向、碰撞修正、片段调度或游戏状态绑定；办公室默认仍为自由检查相机。

全部常规验证由代理在 Mac 上执行，不需要用户逐步确认。Mac 的既有防休眠进程保持运行，直到完整移植结束或用户要求恢复。

## 格式与原版证据

以下原生地址仅适用于中文 EXE SHA-256 `a3c9360321d4e4687b1a8a095f514c6c38c327119d8f52aafe664f02bc51679e`。隔离执行使用 Unicorn，不启动 Windows 游戏。

`0x41960e..0x419874` 是原加载器的 220 字节关键帧分支；另有 176 字节旧分支，本步明确不接受。不能用 OBJM 文件头的两个零字段推断 ANIM 版本。当前适配器要求下面的完整布局、精确数据边界及已验证字段；不猜测旧布局。

| 记录 | 字段 |
| --- | --- |
| ANIM 头，72 字节 | 名称/标识原字节保留；偏移 68 为轨道数 |
| 轨道头，24 字节 | 偏移 0 为 FRAM ID，4..16 本批均零，20 为关键帧数 |
| 关键帧，220 字节 | 0 为 float 时间；4/20/36 为位置/旋转/缩放有效标志；8 为位置，40 为缩放，116 为 XYZW 四元数，160 为曲线标志 |
| 其他关键帧字段 | 包括缓存矩阵和链表索引；不把磁盘缓存当作采样结果，源数据仍由不可变模型保留 |

12 个二进制相机模型共 **19 条轨道、3,966 个关键帧**。上一阶段统计的 21 个相机命名节点包含没有 ANIM 轨道的基础节点，两者不是同一计数。另 3 个 DirectX 文本相机仍未解析。当前资产均包含完整 S/R/T 通道、线性位置插值；稀疏通道、曲线路径、无效节点、重复绑定、不递增/非有限时间、非单位四元数、截断/多余字节均明确拒绝。

`0x4072d9` 预处理关键帧并重建 S×R×T 矩阵，`0x406c6b` / `0x407c1c` 选择关键帧。位置和缩放使用 `0x409520` 线性插值，旋转使用 `0x523d9c` 最短弧四元数插值；近似同向分支不额外归一化。C 实现保留了影响数值结果的 float 中间存储。

原加载器调用 `0x406c5a(track,1)` 开启轨道循环。循环仅在 `time > last_key` 时触发，使用 `trunc(time) % trunc(last_key)`，不是浮点取余。例如办公室末键为 171：171 保留末键，171.5 采样 0，172.5 采样 1。独立采样接口也支持显式关闭循环，此时越过末键保持终态。

`0x402780..0x402789` 把输入秒数乘 60；相机控制器传入半秒数系数，所以诊断播放器每个 60 Hz 固定步推进 0.5 个源 tick。**这只是已核对的输入换算与裸轨道播放速度**；`0x4026fe` 还含片段起止、速度、切换/过渡状态，尚未移植完整调度器，不能把诊断播放器的持续计时当成原游戏流程时钟。

## 模块与运行入口

- `runtime/model/animation.[ch]` 是 CPU 适配器，借用不可变 BkModel，拥有已解码的轨道。输出世界矩阵；未动画化节点保留基础局部矩阵，父子仍为 `local * parent_world`，允许父节点存于子节点之后。失败不修改调用方输出。
- `bk_model_pose_world_matrices` 复用原层级遍历，接受外部局部姿态，基础模型及静态实例不被改写。相机动画对象先于借用的模型销毁。
- 注册 `BK_SCENE_CAMERA_TRACK`，显式加载 `bk3_04/cam00_02.x`、采样 `Cam_AUTO`，用已验证的相机逆矩阵与原版投影绘制办公室。没有把原文件姿态加上猜测的角色位置。
- Switch 默认办公室；按 **X** 在自由检查与裸轨道检查之间切换，轨道中 **A** 重启、**B** 返回标题、**+** 退出。控制提示明确标注 `RAW CAMERA TRACK / ACTOR BINDING PENDING`。切换仍先构造完整新场景，再销毁旧场景；缺失/损坏相机包明确失败。
- 主机入口 `--scene camera-track`。主机应用按真实经过时间更新，`--frames` 是渲染帧数；确定性 30-tick 截图由 `scene-probe` 显式推进固定步产生。

## 控制器锚点继续追踪

`0x4ec78d` 在全局 `0xbef784=0` 时，调用 `0x4bdc12(0x71af38, 0x728de8)`。状态 1 根据 `0x729780` 调用其他控制器，状态 2 不进入这两个分支。它们与办公室资源初始化是不同层面的条件，不能仅凭文件选择就跳过实际状态机。

`0x4bdc12` 的边界捕获确认以下顺序：

1. 将动画根节点平移到角色 `+0x29c/+0x2a0/+0x2a4` 位置。
2. 以 `0.5 * 秒数` 推进动画。
3. 取轨道节点世界位置，以 `旧位置 + (轨道位置 - 旧位置) * 秒数` 平滑；中间结果存为 float。
4. 满足区域检测时，再以 `4 * 秒数` 向修正目标平滑。
5. 用角色 `+8` 指向的头部节点世界位置调用朝向函数，然后设置已平滑的相机位置，再保存矩阵快照。
6. 动画达到终点时清角色 `+0x579` 状态。

**朝向调用在位置设置之前。** `0x425196` 的模式 0 读取既有相机世界位置构造方向，不能擅自改为先设置新位置再朝向目标。本步对照捕获了顺序和参数，未执行真实角色动画、区域几何检测或这段朝向函数；运行时还未接入该控制器。
