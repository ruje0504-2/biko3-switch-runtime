# 普通结局的双视角 GPU 绘制

2026-09-28。已经将上一阶段的真实 `4d9898` 场景适配接到 Vulkan 双视角绘制。范围是已恢复的十组普通结局资源；完整 flow16、其他结局加载器和控制阶段尚未接入应用。本阶段未新增 Switch 实机结局验收。

## 实现

`bk_ending_normal_render_create_special` 在加载阶段额外保留主体和辅助模型各一份 GPU 几何、蒙皮矩阵、材质和队列状态，以及两个灯光快照。背景不重复创建。原普通构造仍只分配普通绘制所需资源。

`bk_actor_render_create_view` 共享原纹理、眼纹理、白纹理和排序身份，分别拥有几何和 prepare 版本；共享资源引用计数允许源实例或副实例先销毁。借用的视频 surface 在构造时复制，两视角使用同一 `poi.avi`，只由显式 movie_step 推进。视角构造不再次读取归档或上传纹理。

两遍分别执行实际场景树发布、相机视图、材质读取、全局队列和灯光快照；共享同一个原灯光登记表，保留模式1到模式2的启用状态。每个视角内的后续 flush 检查演员世界缓存没有变化，防止旧 batch 引用被重新 prepare 的数据。

CPU 准备阶段记录完整 End→特殊视口→深度清除→Begin→第二遍→主视口顺序。活动 Vulkan 帧执行第一遍、切换视口、`vkCmdClearAttachments` 清深度、第二遍和主视口恢复；原 End/Begin 被合并到这个实际 GPU 命令序列，不引入额外提交或 CPU 等待。BOM 的 GPU 变形回调仍在蒙皮后执行。

构造阶段验证实际 BOM 的适用条件：辅助模型是只读源，所有目标落在主体同一子网格，选中的目标顶点均参与蒙皮重算。当前十组每组两条映射满足条件；未知拓扑明确拒绝，不将普通资源的结论推广到其他加载器。

没有新增生产帧内分配、读回或 CPU 蒙皮回退。失败使整个准备结果失效；已执行的 CPU 场景前缀按原接口保留。

## 验证与边界

- 原调度和相机/节点/材质的指令依据来自已完成的 `ending-special` 与 `ending-special-scene` 对照；本阶段不重复将这些旧计数列为新的原版光栅化验证。
- `ending-render-probe --special`：十组配置共320帧，31,924队列项、3,415,936个顶点数值比较，普通/ASan最大相对误差 `3.68802e-7`。其中280帧实际双视角、40帧空事件，另有40次纯重绘；视频每逻辑帧仅推进一次。
- CPU 参考先按原单份顶点缓冲顺序执行两遍，再从独立初始缓冲计算第二遍。320个被第二遍提交的相关网格一致，其中240个为BOM回写目标。GPU两份缓冲各自与其参考值一致；隐藏、alpha0、四类disabled值和重复提交均保留。
- 新增20次非法视口/错误BOM计数预检，准备失败后无可用绘制结果；原缺视频构造与资源回收检查继续通过。
- `actor-view-probe` 使用合成彩色矩形，80帧、268,800个颜色通道差不超过1/255；第二/第三视角准备不覆盖第一份材质或矩阵，局部清深度保留其他区域，capture/LOAD保留深度。8次副视角创建各只增加两个几何缓冲分配，没有复制纹理；源先释放和副本先释放共4轮均可继续正确采样，最终资源回到基线。
- 原常规绘制回归320帧、22,980队列项、1,707,968顶点，普通/ASan保持最大相对误差 `3.68802e-7`。所有GPU探针帧间分配稳定。
- 纯手柄原标题→选人→雨天剧情→游戏→两次拍照→暂停→返回标题，普通与ASan通过，最终RGBA SHA-256均为 `6cb3f86d35377e9ce3612df07a781789c9485d385e644844be8524257f19691f`。
- 两项架构检查和指定 Mesa NVK Switch 构建通过，未定义符号0；源码NRO `8f11bae1c309da65e5bea94008033922d61d62e18e0a660df738afdda1e930d6`。已有天气/原标题交付包保持冻结。

ASan使用 `detect_leaks=0`；GPU资源计数覆盖GPU生命周期，不等于完整CPU泄漏扫描。新合成像素和真实网格缓冲检查不等同于 Windows 原版整帧截图对照，也不等同于 Switch 性能验收。
