# 第一场景移动镜头后的灯光闪烁

2026-10-01。用户确认前一版仍会闪烁，并补充：停止操作后还会持续几秒；最新范围是第一位角色的第一个室外场景最明显，室内应该不闪，不能归因于雨雪。`lighting-motion-depth.md` 的合成平面测试不足以证明这次实机问题已解决。

本轮修复了前一版反向深度转换仍有的矩阵舍入问题，并在第一场景的真实墙面/发光贴片几何上取得旧路径失败、新路径通过的主机对照。没有新的 Switch 实机结果，不能据此宣布用户视频里的全部闪烁已经消失。机器可读证据见 `lighting-motion-transform-verification.json`。

## 原因和改动

前一版在完整的 float 模型×视图×投影矩阵上计算 W−Z。视图旋转和不同模型原点已经使相近的 Z/W 系数分别舍入，事后相减无法恢复丢失的有效位；D32 反向深度本身不能弥补这一步。

现在在投影矩阵阶段先构造反向深度行，以 double 与视图矩阵相乘、保存四个系数，再与每个对象的世界矩阵相乘，最后一次转换为 GPU float。`actor_render` 和 `static_world` 都使用这条路径。原 CPU 矩阵仍负责 X/Y/W，原镜头、near/far、投影、灯光公式、材质、排序、透明度和 4:3 画幅保持。没有新增 GPU pass、绘制、缓冲分配或同步等待；每个对象增加四个四项 double 点积。

`bk_camera_follow_pose` 的位置追随在释放操作后仍逐帧收敛，因此不能把“手指松开”当作矩阵已经固定。测试分别统计主动移动、三秒减速、完全固定三个阶段。这与用户描述相符，但测试的相机轨迹是明确构造的夹具，不冒充视频中的精确输入回放。

## 对照

两项测试均在普通和 ASan/UBSan 构建执行，两个构建的摘要完全一致。`--legacy` 使用同一后端、同一几何和灯光，只回到前一版合成矩阵后转换的路径；它应返回 1，默认修复路径应返回 0。

| 测试 | 每个构建覆盖 | 旧路径 | 新路径 |
| --- | --- | --- | --- |
| 不同模型原点、旋转/平移相机、固定照明 | 2,880 帧，四距离、两种提交顺序 | 109,056 错误像素，248 次覆盖变化；减速阶段也失败 | 错误像素、覆盖变化、亮度错误均 0 |
| 第一室外场景实际墙面与发光贴片 | `bk3_03/m00_10.x`，11 组几何×2 个释放位置，7,920 帧 | 移动/减速/固定分别 6/8/0 个错误中心像素，11/1/0 次可见性变化 | 三阶段错误和变化均 0 |

真实几何测试保留局部顶点和静态世界矩阵，CPU double 射线确定前后关系；墙面与光片分别使用常量红/绿自发光来隔离遮挡问题，并保留光片加法混合、不写深度。961×721 的奇数尺寸使中心采样恰好落在 CPU 参考射线上，接近 Switch 的 960×720 内容区域。它不是原版 Windows 截图或完整灯光公式验收。

探索中的阴性结果和限制也保留：四个街区正视角的 70 组、25,200 帧在旧/新路径都通过，不能作为旧故障复现；第一街区 65×49 极低分辨率斜视角压力测试，旧/新仍有 23/13 个错误中心像素。后者涉及低分辨率光栅精度，未声称所有距离/分辨率/共面边缘都已解决，不能把它计作通过。正式近原生分辨率测试仍保留严格的零错误要求。

## 复现入口

```sh
cmake --build build --target depth-transform-probe light-surface-motion-probe --parallel 4
build/depth-transform-probe
build/light-surface-motion-probe local/game/MAINDIR/Data
# 下列两个命令应显示 FAIL 并返回 1，用于证明旧路径确实触发问题：
build/depth-transform-probe --legacy
build/light-surface-motion-probe local/game/MAINDIR/Data --legacy
```

ASan/UBSan 使用 `build/asan-static/` 中同名目标，并设置 `ASAN_OPTIONS=detect_leaks=0`、`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`。原始资产保持只读，不纳入 Git。
