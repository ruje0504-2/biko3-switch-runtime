# 4D39E6 资源与 48181F 表现阶段

本轮把 4D39E6 的真实资源链接入结局场景，并恢复 48181F 的 CPU 表现顺序。

4D39E6 使用 `bk3_12/hNN_12.xan`、对应 FAM、眼资源和两条相机轨道；主体为森林根 0，轨道为 1/2，外层背景为保留 owner 的根 3。该资源没有 BOM。`h02_12` 的 TEXA 保持模型不透明数据，LIGA 仍在构造阶段明确失败，避免把未恢复的动态光效伪装成已实现。缺少可选 `A_okosi` 时沿用真实主体根作为目标缓冲，必需 `A_kuch` 仍严格检查。

48181F 已按原调用顺序完成独立 CPU 控制器：背景完整推进，按 `721EEC` 和活动片段选择主体的 `.3/.5/.2` 速率或 `402E18` scheduled plain 调度，随后执行四次材质 alpha、可选附属隐藏、森林发布、表情/眼睛/眨眼、组 4 gaze、语音包络和嘴型。新控制器不拥有资源、GPU、音频或 UI；前置 47DC79 仍显式失败，因此 phase4 目前不会绕过未恢复的父控制器。

47DC79 的 state4 入口已恢复为独立控制器：先按原顺序轮询两个媒体 owner，播放中保持无操作；空闲后按 group 2/3/4 选择下一状态、表情、clip5 和 camera mode，group 0/1 额外执行组声音，再准备下一组资源并清除原缓存。控制器只负责可验证的 CPU 前缀，47DC79 的后续 state5/6/7、媒体播放与完整 phase 仍保持显式未实现。
