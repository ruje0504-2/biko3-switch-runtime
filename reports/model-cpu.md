# M1.1：CPU 模型解析与节点层级

**本阶段已完成 CPU 解析；M1 静态场景整体仍在进行中。** 当前标题程序没有加载或绘制模型，不能将本报告当作 3D 画面、动画或 Switch 实机验证结果。

## 实现

- `runtime/model/model.h` / `model.c`：独立 CPU 模型模块，加入主机和 Switch 的 `bk_model` CMake 目标。
- 读取 OBJM chunk、网格/分组子网格、60 字节顶点、16 位三角形索引、MATE、TEXT、FRAM。
- 保留原始名称字节、对象 ID、材质值、源矩阵、未知 chunk 和字段，拥有独立源数据副本。
- 将材质、纹理、父节点、网格 ID 解析为数组索引；拒绝缺失引用、重复/零 ID 和层级环。
- 迭代生成世界矩阵，支持父节点在文件中晚于子节点，避免深层递归。
- 输入截断、尺寸/计数越界、非有限的已使用浮点值、非法三角形索引、路径型纹理名、重复 chunk、空几何均明确失败。
- DirectX 文本 `.x` 与未知 OBJM 头版本明确返回 `BK_MODEL_UNSUPPORTED`。没有用空模型代替成功。

本次不执行 ANIM、ENVL、MORP、MATA、TEXA 或粒子；这些区块只保留原始字节。材质数值与纹理绑定已读取，但多纹理阶段、透明/混合状态和原版灯光尚未映射到 Vulkan。

## 已核实的布局

本次 247 个文件均为 `OBJM` 加两个零 DWORD 的 12 字节头。后面是 `(fourcc, uint32 size, payload)`；文件值均按小端读，不把文件直接强制转换为 C 结构体。

| 记录 | 跨度 | 已使用字段 |
| --- | ---: | --- |
| MATE | 140 | 名称 `+0`，ID `+64`，四组 RGBA `+68..+128`，power `+132`，未解释值 `+136` |
| TEXT | 204 | 名称 `+0`，ID `+64`，文件名 `+68`；其余字节保留 |
| MESH 头 | 72 | 名称 `+0`，ID `+64`，子网格数 `+68` |
| 子网格头 | 332 | 材质 ID `+4`，纹理 ID `+8..+20`，顶点数 `+64`，索引数 `+68`，纹理阶段数 `+72` |
| FRAM | 396 | 名称 `+0`，ID `+64`，矩阵 `+68`，父 ID `+172`，网格 ID `+176` |

子网格数不等于 1 时，每个子网格前另有一个 72 字节命名头。顶点保留位置、beta 槽、法线和四对纹理坐标的原始布局；本阶段只检查会被当前静态路径使用的前 9 个 float，未使用的扩展坐标原样保留。beta 槽**没有按骨骼权重解释**。

原版创建顶点缓冲传入 `0x416`，并采用 60 字节跨度；其字段排列与 Direct3D FVF 的位置/beta、法线和纹理坐标组织相符。[Microsoft FVF 文档](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dfvf)。这个布局证据不能替代尾行3 自己的蒙皮/动画逻辑。

## 验证入口

```sh
./build-host.sh
python3 -m unittest discover -s tests -p 'test_model.py'
python3 tests/audit_models.py local/game/MAINDIR/Data
build/model-probe local/game/MAINDIR/Data/bk3_03.pp m01_04.x
local/venv/bin/python tests/original_matrix_oracle.py \
  '尾行3 [汉化]/去码汉化补丁/汉化/尾行3中文版.exe' local/game/MAINDIR/Data
./build-switch.sh
```

`fuzz-model` 对合法合成 OBJM 做 12,000 组确定性变异/截断，在 ASan/UBSan 下验证解码、层级计算和释放路径。有些变异仍然是有效文件，不要求全部被拒绝。新增六项模型单元测试涵盖数据所有权、分组、索引/引用错误、层级环、截断、格式分类、矩阵顺序、父节点后置和溢出。

Switch 产出是新增 CPU 静态库 `build-switch/libbk_model.a`，尚未由标题场景引用。现有标题 NRO 的功能不变。下一步按 M1.2 核对渲染状态和材质语义，再把模型、纹理和节点实例接到 `BK_SCENE_STATIC_WORLD`，不跳到动画或玩法。
