# GPU 蒙皮与 CPU 热路径优化（2026-09-28）

本轮针对 Switch 1GHz CPU 掉到约53FPS、GPU负载低的反馈，已实际启用 Vulkan compute ENVL 蒙皮，并删除重复排序、矩阵计算和无用分配。使用锁定的 Mesa26.2.2 NVK，commit `5dba7886c56460ff47c3038e323d07b9547d6212`。原计时/FPS、独立音频线程和原有存档格式保留。镜头贴墙输入绑定另已修复，见 `camera-probe-fix.md`。源码审查与后续候选见 `cpu-static-review.md`。

## GPU 路径

- `scene/skin_upload` 在加载时将原 ENVL 骨骼顺序转成逐顶点的有序操作表。重复索引、beta<=.001覆盖、累计>=.999补足均在CPU按既有原版数学预计算；没有重新归一化权重。
- `render/vulkan` 每个演员持一个骨骼 palette，各网格共享并保留其生命周期。compute 每64顶点一组，写入原 lit vertex buffer，随后通过 compute→vertex input 内存屏障供绘制使用。位置为世界坐标、ENVL 绘制仍用单位矩阵，法线不在蒙皮中归一化。
- 每帧只在矩阵改变时上传 palette；普通刚性属性不再重复转换/上传，MORP、材质变化仍正确刷新源属性。未受影响顶点保留源值。删除待计算网格会从队列摘除，owner 先释放 palette 也不会悬空。
- 主机/ Switch 均默认 GPU；`BK_CPU_SKINNING=1` 是显式 CPU 对照开关。没有静默失败回退。GPU输出只在诊断工具中读回，正式游戏不逐帧读取蒙皮结果。
- shader 使用 Vulkan1.0 SPIR-V 和 float32，不要求 float64。原 CPU 数学包含 double 中间值，GPU结果不宣称逐位一致。

- 同一probe检查源属性改变/恢复、活动帧内拒绝更新、非法矩阵和尺寸、未变palette不重复派发、共享palette与待执行对象销毁。

## 性能与画面差异

同一M4/MoltenVK、固定60Hz输入回放、1100帧，各三次交错运行旧CPU、新CPU、新GPU。排除每次首个含加载的2秒日志窗口；一次新CPU运行结束过快，无第二窗口，因此该次不进入窗口中位数。完整原始窗口和图像摘要在JSON中，没有删去慢窗口。

| 主机诊断路径 | 每帧上传中位数 | CPU侧帧耗时估计中位数 |
|---|---:|---:|
| 优化前 CPU 蒙皮 | 1.12 MiB | 2.11 ms |
| 去重复后的 CPU 对照 | 1.12 MiB | 1.88 ms |
| 默认 GPU 蒙皮与去重复 | 0.18 MiB | 1.90 ms |

上传约减少84%。耗时估计为 update+draw+end+tail 减 fence/acquire/present，仍含调度和其他等待，不能视为硬件CPU cycles。M4上GPU路径与新CPU路径接近；不能把它换算成 Switch 提升百分比或保证60FPS。此组测量先于镜头输入修正，最终版本另做同样1100帧回读核对。

CPU优化前后图像逐字节一致。GPU float32与旧CPU图像在921600像素中17像素不同，22通道改变，平均通道绝对差0.00015381/255；个别覆盖边缘差255，因此不能宣称所有像素误差<=1。此为主机数值/栅格结果，不是Windows原版截图对照。
