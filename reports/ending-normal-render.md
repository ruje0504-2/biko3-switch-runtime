# 普通结局常规 GPU 绘制

新增 `scene/ending_normal_render`，组合普通结局已加载的主体、辅助模型、背景、FAM、眼纹理、BOM、共享灯光和真实 AVI。这里只提供原 `4a4701` 的常规绘制服务；尚未接入完整 flow16，也没有替代必需的 `4d9898` 特殊绘制、界面、声音或事件控制器。

## 实现

- 渲染器借用 `ending_normal_assets`，背景必须先完成外层加载。拥有三组 GPU 模型、三组队列/灯光快照、BOM 回调和 AVI；GPU owner 必须先于 CPU 模型销毁。
- 常规 mode1 按原描述符绘制背景、主体及可选辅助模型。event7 空描述符没有几何提交。未知对象、未支持的模式及失效快照显式失败。
- 原正常拓扑中，最后加载且可见的背景根被遍历时，先发布全部已连接的角色和镜头缓存。此后主体、辅助根的遍历不会再次改变这些矩阵。因此每个模型每帧只准备一次几何，三次 flush 使用独立灯光和排序队列，保留跨模型节点提交和重复项。
- 上述复用依赖可见、最后挂接的背景根；接口检查该条件。隐藏背景或改变其拓扑的路径仍需另行实现，不能静默复用过期缓存。特殊第二镜头也不能通过重准备同一 actor 后复用旧 batch 实现。
- 真实相机轨道含检查几何，并非全部无网格。原常规选根不会提交这些轨道；意外选中其几何时明确拒绝，不能无条件丢弃。
- 主体使用 FAM/眼状态及可选材质实例；辅助模型使用实际 BOM 的 MATA/MORP。双方准备完成后再截取 BOM 源世界矩阵/禁用标志；回调在 GPU 蒙皮后、材质 alpha 早退前执行。生产路径无 GPU 顶点读回，无帧内资源分配。
- 十种普通入口的 `D_moza.bmp` 唯一目标都在主体，五组纹理索引依次为8、2、2、2、1，辅助与背景没有别名。加载 `bk3_18/poi.avi` 并检查原256×256尺寸，借用视频表面且保留原纹理排序身份。
- `4e1473` 是对已有 AVI 的 `521ed2` 更新调用。视频推进作为独立服务接受原有进程时钟；普通 prepare 和纯重绘不会推进视频。首次请求前沿用已定义的可移植黑色初态及 RGB555/DIB 策略，不声称复现原驱动未初始化显存。

## 验证

固定 EXE SHA-256：`a3c9360321d4e4687b1a8a095f514c6c38c327119d8f52aafe664f02bc51679e`，素材为日文零售版。

`original_ending_regular_walk_oracle.py` 在十种实际装配拓扑上执行原 `42261a/42273b` 和原矩阵栈/D3DX。240个显式组件帧、600次绘制遍历、529080份世界/父缓存矩阵与10578次网格节点提交一致，最大误差0。背景之后的各次常规遍历也逐值证明缓存保持。动画局部矩阵为共享输入，GPU 入队边界使用每网格节点一个标记；这不涵盖原 Windows 光栅化或完整事件更新。

`ending-render-probe` 普通与 ASan 都通过：

- 十配置、320组件帧、22980个队列项；包含主体/辅助隐藏、材质 alpha0、原 BOM 禁用值0/1/2/-1、有无辅助根及40次空流程绘制。
- GPU ENVL 后的 BOM 目标/源缓冲与 CPU 参考比较1707968个顶点，最大相对误差 `3.68802e-7`；包含40次纯重绘后的再次读回。读回仅用于该诊断程序。
- 320次视频帧变化；prepare/纯重绘保持视频帧。十次缺 `bk3_18` 的构造失败释放已建立的 GPU 资源，随后可以正常构造。
- 帧内与十次卸载后 GPU 活跃分配/字节保持预期；确认实际发生 GPU 蒙皮 dispatch，未走 CPU 蒙皮替代。ASan 使用 `detect_leaks=0`，不宣称 LeakSanitizer 通过。

两项架构规则通过。指定 Mesa NVK 全工程交叉构建通过，Mesa commit `5dba7886c56460ff47c3038e323d07b9547d6212`，当前 NRO SHA-256 仍为 `f1ff22eae11b17b6740e2c9a1c0693483022e561e5849bcfd2cf5ed4a3b8efa6`。新组件未被应用引用，所以最终 NRO 的死代码移除后哈希不变；不能据此宣布结局已在 Switch 接入或实测。

本轮没有修改既有应用/底层 GPU 路径，未重复已通过的全流程回归。原标题和天气交付包保持冻结；用户已确认的是雨天实机效果，防休眠继续。
