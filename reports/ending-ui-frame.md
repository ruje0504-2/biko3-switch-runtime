## 实现

`scene/ending_ui_frame` 按原顺序执行结局图片74、首次初始化、指针位置、运动量、工具栏、分支提示、游标选择与显示、共享黑幕、重载及尾部提示。重载 action49 提前返回，不访问尾部的字段或服务。失败保留已执行的原顺序前缀，输出 `complete=0`，禁止提交该帧。

所有子绑定借用同一 frame/control/auxiliary/notice/目标/进度状态，身份不一致直接拒绝。黑幕和其请求字节直接借用会话 `common_hud`；工具栏新增共享字节入口，避免读 `frame` 中仅供独立诊断的旧别名。实际游戏更新器将来还需处理 `frame.finish_fade_stage/finish_blocked/transition_action/curtain_wanted` 与 UI/公共状态之间的别名同步。本组件不会用复制的黑幕掩盖这一责任。

`scene/ending_ui_batch` 在 CPU 调度之前保留旧图片所有者，调度成功后按黑幕边界分别绑定旧/新图片。应用重载释放其引用后，旧纹理仍能完成当前帧。相同所有者的全部精灵快照先合并再准备网格，保留重复槽的不同坐标和原绘制顺序；不会用后半帧覆盖前半帧。黑幕借用已有 `curtain_render` 和真实 `ma_01.tga`。纯重绘不推进 CPU 状态，不分配新 GPU 资源。

图片引用计数只用于顺序场景生命周期；创建、准备和最终释放均在活动 GPU 帧之外。同一图片所有者在完成批次绘制前不能被另一个批次重新准备，否则会覆盖其网格。这是显式接口约束，不宣称可并发准备。
