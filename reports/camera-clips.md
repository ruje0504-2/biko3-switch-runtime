# M1.4 相机片段调度与朝向基础 — 0.3.4

已将原 XAN 片段播放器接入办公室相机检查场景：播放范围、速度、循环、自动衔接和 SRT 过渡都有原函数数值对照。朝向及跟随平滑已实现为独立 CPU 姿态接口，尚未绑定真实角色与游戏状态。**默认仍是办公室检查视角；完整游戏移植和 M1 视觉验收均未完成。** 常规构建、数值与内存验证由代理完成，不要求用户逐步确认。Mac 防休眠保持到完整移植结束。

## 原版依据与文件布局

以下地址只适用于中文 EXE SHA-256 `a3c9360321d4e4687b1a8a095f514c6c38c327119d8f52aafe664f02bc51679e`，由 Unicorn 隔离执行，不启动游戏进程。

`bk3_04.pp` 实际含 15 个相机 `.xan`，每个 20,880 字节。`0x401074` 先读取两段 256 字节模型名，再读取 `0x4f90` 字节结构。该结构含运行时指针、缓存时间与速率，不能直接恢复为新播放状态。本实现只读取已验证的配置，创建全新的运行时状态；不是存档读取器。两段模型名必须一致且为受支持的资源文件名。

结构偏移 `0x190` 起有 128 个、每个 `0x9c` 字节的片段。下表偏移以片段起点为基准：

| 偏移 | 含义 |
| --- | --- |
| `0x00` | 0 为一次播放，1 为循环 |
| `0x48` / `0x50` | 循环重入的时间轴 tick / 时间轴终点 |
| `0x54` / `0x58` | 源动画起止 tick；两者均零表示空槽 |
| `0x70` / `0x74` / `0x78` | 自动衔接开关 / 下一槽 / 衔接前循环次数 |
| `0x7c` | 配置的过渡 tick |
| `0x44`, `0x5c`, `0x60`, `0x64`, `0x6c` | 运行时计时、速率、源 tick、循环计数等；不恢复磁盘值 |

有限、非负时间和正时长、模式、引用完整性均检查；零时长、旧离散帧模式、不同模型名、未支持的非零字段明确拒绝。空槽不能选中；损坏文件、无效步长或溢出不修改已有播放器输出/状态。源文件字节不被写回。

## 播放语义

- 显式选择来自 `0x401d24`（微小过渡）和 `0x401f71`（配置过渡）。速度重算为 `(源终点 - 0.1f - 源起点) / 时间轴终点`，保留原 float 存储；不能使用 XAN 的旧缓存速率。
- `0x4026fe` 将输入秒数乘 60，并独立维护源 tick 和时间轴 tick。原相机分支传入半速秒数，所以 60 Hz 固定步相当于 **0.5 个时间轴 tick**，不再解释成固定 0.5 个源动画 tick。
- 选择后的第一次推进丢弃传入时长；微小过渡的第二次推进仍提交过渡终态，然后才进入普通推进。这些边界严格保留，没有人为优化成直接跳转。
- 一次播放到达终点后保持。循环重入配置的时间轴起点，结束/循环标志按原逻辑保持，重新选片段时清除。自动衔接 `0x4025b9` 改变活动槽，但当次仍使用旧片段指针提交姿态；下一次推进使用新槽。不将一次长步分割成多次循环来改变原行为。
- `0x408927` 分别采样过渡两端：旋转使用最短弧 slerp，缩放线性插值，位置通过 `0x42d92f` 的四次 float lerp 实现 smoothstep 缓动。并非直接对矩阵或位置做一次线性混合。保留各次 float 舍入。

办公室 `cam00_02.xan` 槽 0 是一次播放，源范围 **151..166**，时间轴终点 **400**，没有自动衔接。槽 2 的 `68..108 / 350` 循环两次后衔接槽 4，槽 4 的 `129..159 / 350` 循环两次后衔接槽 0。槽 10 是另一个 `151..166 / 400`。这与 0.3.3 将整个 0..171 轨道按 30 源 tick/秒播放的诊断入口不同；旧报告保留为历史快照。

## 朝向与平滑

`bk_camera_aim` 实现 `0x425196` 模式 0：从既有相机世界位置看向目标，Y 轴为向上方向。`0x522922` 在单位长度平方的 ±1e-5 范围内跳过归一化，该细节已保留。目标重合、近零或垂直造成退化基向量时明确失败，不向渲染器提交无法求逆的矩阵。

`bk_camera_follow_pose` 只接受已提供的世界点和已有姿态，恢复 `0x4bdc12` 的平滑计算及顺序：位置向采样点以 `seconds` 平滑，可选向修正点以 `4*seconds` 平滑；朝向基于**旧世界位置**，最后安装平滑后的位置。原函数的差值、乘积、相加分别存为 float。此接口不加载角色、不查询障碍、不选择游戏镜头，也没有在场景中使用虚构头部位置。

## 工程接入

- `model/clip` 拥有解码的配置和独立播放器；播放器借用配置，销毁顺序为播放器、配置。完全独立于 Vulkan/libnx。
- `model/animation` 复用单点采样并新增 SRT 过渡接口；姿态失败不修改调用方输出。
- `core/camera` 只接收数学输入，没有 actor/game 依赖；实际角色、碰撞和状态绑定仍由后续上层提供。
- `BK_SCENE_CAMERA_TRACK` / 主机 `--scene camera-track` 改为读取 `cam00_02.xan`，按其引用加载 `.x` 并播放槽 0。初始化/重启执行一次零时长提交，固定步推进只更新 CPU 姿态，绘制只读取姿态。
- Switch 的 X 在办公室自由检查与 XAN 片段之间切换，A 重启片段，B 返回标题，+ 退出。提示明确为 `XAN CAMERA CLIP / ACTOR BINDING PENDING`。构造失败传播错误，仍遵守先创建新场景再销毁旧场景的约定。
