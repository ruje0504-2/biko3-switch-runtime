# 结局交互中的齐次蒙皮修复

2026-09-29。修复当前普通结局第四角色（group3）在真实输入命中 target26 后的蒙皮拒绝。此次不改画幅，输出仍使用居中的 4:3 内容；不覆盖冻结交付、不推送、不生成整包，Mac 防休眠保持。

## 原因和原版依据

修复前 `local/ending-skin-homogeneous-diagnostic.log` 在实际动作帧报告 bone449 的第四列为 `(0,0,0,0.99999994)`。CPU 和 GPU 绑定原先都严格要求 W=1，因此原父节点求逆/组合中的合法浮点尾差被误判为不支持的矩阵。

固定 EXE SHA-256 为 `a3c9360321d4e4687b1a8a095f514c6c38c327119d8f52aafe664f02bc51679e`，所有地址仅适用于该版本。原 ENVL `0x41075e` 对每个影响调用位置函数 `0x522b0d` 和法线函数 `0x522bd9`。位置函数先分别存储 float XYZ 和 W，比较存储后的 W−1 与 float 常量 ±1e-5；包含等号的容差内保留 XYZ，容差外先求扩展精度 1/W，再乘已存储 XYZ。常量来自 `0x53fad4/0x53fad8/0x53fadc`，实读为 1、−9.999999747378752e-6、+9.999999747378752e-6。法线只乘原 3×3，不做齐次除法或归一化。

此前尚未通过的测试把所有非单位 W 都当成不改变 XYZ；已删除这一错误假设，改为执行原指令并观察实际除法分支。没有通过修改资产矩阵 W 或放宽数值阈值掩盖故障。

## 实现边界

`core/matrix` 新增独立的 `bk_matrix_transform_coord`，保留原始 `bk_matrix_point` 的四分量语义。CPU 蒙皮在原权重顺序之前使用新位置变换，保留 .001/.999 边界、法线、未加权顶点、UV 残留位和原子结果提交。

GPU compute 对 XYZ 使用相同的容差分支，法线保持原规则。常规仿射和容差内常量 W 的 palette 不增加 CPU 逐顶点变换；只有需要真正齐次修正的 palette 才验证绑定位置，失败发生在上传与 dispatch 排队前。相同 palette 仍不重复上传或派发。绑定失败不留下 GPU 分配或半完成绑定。

原零 W 导致非有限输出的情况单独记录；移植端采用明确失败且保留前结果的策略，不宣称与原非有限输出等价。GPU 使用 float 算术，精度结论只覆盖实际执行的回读范围。
