# save 模块契约

capture_file已加入bk_save构建目标：只负责独立输出目录中的暂停背景和相册BMP，以临时文件替换，失败保留旧文件。scene通过输出服务交付字节，app负责接入本模块与平台时钟。它不解析游戏资源路径，不写入原版输入目录。

`checkpoint`、`checkpoint_file` 已实现区域入口存档数据层：5组各10槽，明确保存区域ID、8字节道具和时间；不含进程指针/GPU句柄，也不转储C结构体。移植版每组592字节，包含版本、组别、长度和CRC32，完整校验后才发布输出。写入同目录临时文件，flush/fsync/close成功后rename；不声称目录fsync或断电持久性。错误与不存在严格区分，损坏旧文件不可当成空存档覆盖。

原版560字节`.b3f`提供显式内存编解码，原509c25/509fd2/4af3dc/50d245逐字节对照通过。它没有原生校验和，不自动导入/覆盖原目录。8字节保留字段和时间戳尾部按原版保持；它不是完整现场快照，只支持恢复区域入口。保存页面、应用状态映射和读档重建仍在接入，数据层通过不代表存读档应用已完成。

独立鉴赏表见`unlock.h`/`unlock_file.h`与`reports/unlock-storage.md`。原Yellow40字节显式编解码；移植72字节CRC封装，独立save/unlocks.bku。正常应用启动已读取，缺文件默认0；结局工作表生产/自然自动提交仍待实现，不能用checkpoint道具代替。
